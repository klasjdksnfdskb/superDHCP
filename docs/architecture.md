## 核心设计决策

### 1. MAC 作为基准条目的设计

传统 DHCP 服务器将 v4 和 v6 租约分开记录，superDHCP 以 MAC 地址作为主键将两者统一：
- 一条记录 = 一个终端用户 + v4 地址 + v6 地址
- 支持部分字段为空 (仅 v4 / 仅 v6 / 双栈)
- 查询效率：MAC 主键 + 复合索引支持多维筛选

### 2. VLAN → 地址池路由

```
客户端 DHCP 请求
  → 中继代理注入 Option 82 (Circuit ID 含 VLAN)
  → PoolManager.find_pool_by_vlan(vlan_id)
  → 返回匹配的 AddressPool
  → 从该池的子网中分配 IP
```

### 3. 自定义组织架构标签

- 服务端内部维护，客户端完全无感知
- `custom_tags` 表的 `parent_id` 自引用实现无限层级
- 通过 `full_path` 方法生成完整路径（如 "中国/广东/深圳/南山区"）
- 租约关联标签后，可在查询和 CSV 导出中呈现

### 4. DHCPv6 双模式支持

| 模式 | 地址来源 | 配置来源 | 租约记录 |
|------|----------|----------|----------|
| 有状态 (Stateful) | DHCPv6 服务器分配 | DHCPv6 服务器 | ✅ 完整记录 |
| 无状态 (Stateless) | SLAAC (RA) | DHCPv6 信息请求 | ✅ DUID + 模式标记 |

### 5. 高并发设计

- **数据库连接池**: 40 基础 + 20 溢出 = 60 并发连接
- **异步 IO**: asyncio + udp 多进程处理 DHCP 请求
- **批量写入**: 租约批量 flush，1000 条/批
- **PostgreSQL 优化**: 分区表 + 复合索引 + JIT 关闭

### 6. 安全设计

- JWT (access + refresh) 双 Token 机制
- bcrypt 密码哈希
- 三级角色 (superadmin/admin/viewer)
- 操作审计日志 (audit_logs 表)
- CORS + 安全头 + API 限流
